🎯MVP 定义（最小可行产品）新增

MVP 是项目的第一个可交付里程碑。它不追求完美，但必须端到端可用——用户能输入小说，拿到可用的剧本 YAML。

MVP 范围

功能MVP 标准完整版目标
章节识别 识别"第X章"标记，准确率 > 95% 支持多语言章节标记、无章节小说
场景分割 基于时间/地点关键词分割，召回率 > 80% 语义级场景边界检测，召回率 > 90%
对话提取 提取中文引号内对话，归属率 > 60%
（纯规则引擎极限；低置信度项留空）		 上下文人名推断 + AI辅助，归属率 > 85%
角色识别 基于人名词典 + 简单NER，覆盖主要角色 AI增强NER，覆盖配角+别名
YAML输出 合法 YAML，包含场景/对话/动作字段 完整 Schema，含情感/子文本/镜头建议
用户界面 命令行 CLI（单文件输入输出） Web UI + 在线编辑器
💡 MVP 交付原则：Phase 1 完成即达到 MVP。即使对话归属只有 70% 准确率，只要输出是可用、可人工修改的 YAML，就交付验证。后续阶段在反馈基础上迭代。

LLM 选型与降级策略 新增

层级模型用途成本 (每 1 万字)触发条件
主模型 Claude Sonnet (API) 对话归因、场景分类、情感分析、潜台词检测 ~$0.15-0.30 默认使用（缓存命中则跳过）
备选模型 GPT-4o-mini (API) 同上功能，Claude API 不可用时的 Plan B ~$0.05-0.10 Claude API 超时/限流/不可用时自动切换
降级模式 纯规则引擎 所有 AI 功能降级为规则兜底；输出标注"未增强" $0 API 预算耗尽 / 网络不可用 / 用户选择离线模式
💡 选型原则：Phase 2 的 Prompt 模板设计为模型无关（使用标准 System/User/Assistant 消息格式），确保 Claude ↔ GPT 切换只需更换 API endpoint 和模型名，无需重写 Prompt。Phase 1 完全不依赖 AI，本身即降级兜底。

📋假设与约束 新增

类别假设/约束影响
AI 模型 使用云端 API（Claude / GPT），非本地模型 需要 API 预算；离线不可用；依赖网络
输入格式 输入为纯文本/ Markdown，章节有明确标记 PDF/EPUB 需先转换；无章节标记的小说需人工分段
语言 主要支持中文小说，后续扩展其他语言 中文 NLP 特殊处理（引号格式、分词、网文习惯）
文本长度 Phase 1 支持 3-10 章；Phase 3 需处理 10 万字+ 架构设计需从 Phase 1 就考虑流式/分段处理
开发模式 独立开发者或小团队（1-3人） 功能范围需谨慎控制；避免过度并行
API 成本 每 1 万字约消耗 20K-50K tokens 需设计缓存机制，避免重复调用；Phase 1 不依赖 AI
部署 初期单机部署；Phase 3B 考虑云部署 初期无需 K8s 等复杂基础设施

⚠️风险评估与应对 新增

# 风险描述 可能性 影响 应对措施
R1 AI API 不稳定或成本超预算 中 高 Phase 1 完全不依赖 AI；Phase 2 设计降级模式（规则引擎兜底）；设置 API 预算告警
R2 对话归属准确率达不到可用标准 高 高 输出中标注置信度，低置信度项留空等待人工填写；提供手动修正界面
R3 中文网文格式多样导致解析失败 高 中 收集多种格式样本；设计可插拔的预处理管道；提供格式自动检测
R4 大文本（>10万字）处理性能不足 中 中 Phase 1 即采用分段处理架构；异步任务队列；流式输出
R5 Web 编辑器开发复杂度被低估 中 中 Phase 3A 使用成熟的 CodeMirror/Monaco 编辑器；协作功能推迟到 3B
R6 Scope Creep（范围蔓延） 高 中 以 MVP 定义为准绳；新需求进入 backlog，不插入当前阶段
R7 测试数据版权问题 低 中 优先使用公有领域作品；网文测试用自有创作内容；开源代码不含受版权保护的文本

🔧开发计划

v2.0 调整了任务优先级、新增了关键任务、将原 Phase 3 拆分为 3A（Web应用）和 3B（高级功能）。 单元测试不再作为独立任务，而是贯穿开发全程的持续实践。

Phase 1 核心引擎开发（基础功能 → MVP） 🎯 达到 MVP

📅 预估工期：3-5 周（含缓冲） 👤 主力：1 人 💰 AI依赖：无
🎯 阶段目标：完成端到端小说→YAML转换管道，命令行可用，输出合法YAML剧本。Phase 1 完成 = MVP 交付。
⚠️ 纯规则引擎能力边界说明：中文小说的场景检测、角色NER、对话归属在纯规则条件下难度极高。以下指标为设计目标而非硬性验收门槛——对话归属率 60-70% 即视为可用（低置信度项留空等人工填写），高准确率（>85%）依赖 Phase 2 AI 增强。实际工期取决于中文网文测试样本的覆盖广度。
编号 任务名称 详细说明 优先级 备注
1.1 YAML Schema 设计 定义剧本结构标准——场景(Scene)、对话(Dialogue)、动作(Action)、转场(Transition)等节点字段和约束规则。编写 Schema 设计文档。 🔴 高 阻塞所有下游任务
1.2 中文文本预处理 统一引号格式（支持 "" '' 「」 『』）、段落标准化、编码处理、去除无关元数据。新增 🔴 高 ∥并行 与 1.1 并行
1.3 章节识别与分割 自动识别"第X章"/"Chapter X"等标记，将小说拆分为独立章节，保留章节标题。 🔴 高
1.4 场景边界检测 基于时间/地点/环境变化关键词识别场景切换点；支持"同一场景连续段落"合并。 🔴 高
1.5 角色实体识别 (NER) 基于 jieba + HanLP 提取人名实体；识别角色首次出场；建立角色列表。新增 🔴 高 对话归因的前置依赖
1.6 对话提取与归因 识别四种引号内的对话文本；基于上下文人名+位置规则推断说话者；对不确定项标注低置信度。升级 🔴 高 原 1.4，优先级从🟡→🔴
1.7 基础转换引擎 将解析结果组装为 YAML Schema 格式；格式校验；输出合法 YAML 文件。 🔴 高
1.8 命令行界面 (CLI) 提供 CLI 工具：novel2script input.txt -o output.yaml；支持参数配置（置信度阈值、输出格式等）。 🟡 中 ∥并行 与 1.3-1.7 并行
1.9 Ground Truth 数据集构建 人工标注 3 章小说的"标准答案"——场景边界、对话归属、角色列表；作为 Phase 1 自测和 Phase 2 量化评估的基准。新增 🔴 高 跨阶段资产：Phase 1 启动，Phase 2 持续使用

🔬 Phase 1 → Phase 2 桥接：Failure Case 系统性收集 新增

在 AI 增强阶段开始前，必须先完成一轮规则引擎的 Failure Case 系统收集：
  • 目的：避免 Prompt 工程"闭门造车"——只有明确了规则引擎实际在哪里失败，AI 增强的 Prompt 设计才有针对性。
  • 方法：对 Phase 1 输出的 3 章 YAML 做人工逐场景审阅，分类记录错误类型（对话归属错误 / 场景边界漏检 / 角色别名未识别 / 嵌套引号误拆 / 心理描写混入对话 等）。
  • 产物：Failure Case 分类清单 + 每类 3-5 个代表性样本 → 直接作为 2.1 Prompt 工程的设计输入。
  • 工期：约 0.5-1 周（与 Phase 1 缓冲周可重叠），不作为独立阶段。

Phase 2 AI 增强与优化（智能功能）

📅 预估工期：4-5 周（含缓冲） 👤 主力：1 人 💰 AI依赖：中等
🎯 阶段目标：基于 Failure Case 分类清单，集成 AI 模型针对性修正规则引擎的薄弱环节。对话归属准确率 > 85%，场景分类准确率 > 85%，建立可量化的质量评估框架。
编号 任务名称 详细说明 优先级 备注
2.1 Prompt 工程与模型选型 设计场景分类/对话归因/情感分析的 Prompt 模板；对比不同模型的成本-效果；建立 Prompt 版本管理。新增 🔴 高 阻塞其他 AI 任务
2.2 AI 对话归因增强 使用 LLM 对 Phase 1 低置信度对话重新归因；处理"说话人在对话中间"等复杂模式。 🔴 高
2.3 场景类型分类 AI 自动判断场景类型：内景(INT)/外景(EXT)、时间(DAY/NIGHT/DAWN/DUSK)、地点类别。 🔴 高
2.4 质量评估框架 建立自动化评估指标（对话归属准确率、场景边界召回率、Schema 合规率）；生成转换质量报告。新增 🔴 高 量化 AI 提升效果
2.5 情感基调分析 分析场景情感色彩，标注 emotion 字段（紧张/温馨/悲伤/激昂/平静等）。 🟡 中
2.6 潜台词检测 识别对话中的隐含意义，生成 subtext 标注；标记"话里有话"的对话。 🟡 中
2.7 动作视觉化 将心理描写/抽象叙述转为可拍摄的动作建议；标注"需视觉化适配"段落。 🟡 中
2.8 角色关系图谱 基于对话交互和场景共现，自动生成角色关系网络图（JSON 格式，可导入可视化工具）。 🟢 低
2.9 多格式导出 支持 Fountain 和 Final Draft (.fdx) 格式导出；保留格式兼容性。 🟢 低

转换结果查看 YAML 预览（语法高亮只读）+ 结构化场景列表 PDF 渲染导出预览、分镜板视图 能看懂输出即可；精美预览是增值
编辑器 YAML 源码编辑 + 保存；场景/对话字段编辑表单（基础） 场景卡片拖拽排序、角色筛选视图、批量替换 能修正错误即可；高级交互是锦上添花
协作 —（无协作功能） 评论批注、版本 diff、多人编辑通知 3A 定位单人工具；协作是独立的大功能
导出 YAML 下载 + Fountain 格式导出 Final Draft .fdx、PDF、HTML 渲染 至少一种标准剧本格式可用
部署 Docker Compose 一键部署 + 环境变量配置 K8s Helm Chart、SaaS 多租户、CI/CD 管道 单机可部署即可；云原生是 3B
用户系统 —（无用户系统，单机单用户） 注册/登录、权限管理、用量配额 SaaS 级别功能，3B 评估
🧱 裁决原则：任何一个功能如果在 3A 和 3B 之间存在模糊边界，问自己："没有这个功能，用户还能完成'上传小说→转换→修正→导出'的基本工作流吗？" 如果答案是"能"，该功能进入 3B。

✅验收标准 (Definition of Done) 新增

Phase 1 验收标准（纯规则引擎）调整

  • 输入 3 章中文小说（TXT/Markdown），CLI 命令一行完成转换
  • 输出为合法 YAML，符合 Schema 定义，可被标准 YAML 解析器读取
  • 章节识别准确率 > 95%（标准"第X章"标记）
  • 场景边界召回率 > 75%（基于时间/地点关键词的测试集）从 80% 下调
  • 对话提取率 > 85%（引号内对话不遗漏）从 90% 下调
  • 对话归属率 > 60%（纯规则引擎；低置信度项标注而非猜测）从 70% 下调
  • Ground Truth 数据集 v1.0 可交付（3 章标注完成）新增
  • 核心模块单元测试覆盖率 > 80%
  • 中文引号格式（"" '' 「」 『』）全部通过测试
  • CLI 提供 --help 和基本错误提示

Phase 2 验收标准

  • AI 增强后对话归属准确率 > 85%（在 Ground Truth 测试集上）
  • 场景类型分类（INT/EXT + DAY/NIGHT）准确率 > 85%
  • 质量评估报告自动生成，包含各维度得分
  • 与 Phase 1 纯规则引擎相比，有可量化的质量提升
  • Prompt 模板版本化管理，可追溯每次修改
  • AI API 调用有缓存机制，重复输入不产生重复费用
  • 低置信度输出明确标注，不伪装高置信度
  • Fountain 格式导出可被标准编剧软件（如 Trelby）打开

Phase 3A 验收标准

  • 用户可通过浏览器上传小说文件（拖拽或点击）
  • 转换进度实时展示，大文本不阻塞 UI
  • 在线编辑器支持 YAML 语法高亮和手动编辑保存
  • REST API 有完整的 Swagger 文档
  • docker compose up 一键启动全部服务
  • 支持 10 万字小说转换（单次），内存占用 < 2GB
  • 移动端浏览器可正常使用（响应式）
